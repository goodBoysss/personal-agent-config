# 通用个人习惯

## 沟通与输出

- 所有面向用户的解释、说明和回复都使用中文；代码、命令、标识符保持原样。
- 提供给用户复制的代码和命令必须放在带语言标识的 Markdown 围栏代码块中。
- 多条独立执行的命令分别放在独立代码块中；除非用户明确要求合并，否则不要放在同一个代码块中。
- 命令默认保持完整单行，不添加 shell 提示符、行号或解释文字；说明放在代码块外。完整脚本和代码保留必要换行及缩进。
- 编写流程、数据流、归因或业务逻辑说明时，在有助于理解的地方使用流程图，复杂部分避免只用文字描述。

## 提交与临时产物

- 除非用户明确要求，不主动执行 Git commit 或 push；代码和文档改动都由用户决定提交时机。
- 助手创建的单元测试、回归测试及其他测试文件，在执行验证后自动删除；用户明确要求保留时除外。不要删除预先存在的测试或用户创建的测试。
- 例外：`wx-cli` 项目的单元测试必须保留，包括助手新建的单元测试。
- `.playwright-cli/` 及其内容属于临时浏览器测试产物；测试结束或任务完成时删除，包括当前工作区已有的残留，除非用户明确要求保留。不要提交这些目录。
- 同样清理本次任务创建的临时 PHP/tinker 脚本、临时中间文件和 `.playwright-mcp/` 测试产物；本次任务临时启动的容器用完停止。不要删除用户文件或停止原有服务。
- 收尾检查工作区，只移除本次任务产生的临时产物；不能因为文件未被 Git 跟踪就删除它，正式新增业务文件也应保留。

## 代码与注释

- 新增方法必须添加注释，说明用途，并与所在文件现有的注释格式保持一致；适用于 Controller、Service、Logic、接口声明及内部辅助方法。
- PHP 方法使用 PHPDoc，按实际签名补齐 `@param`、`@return`；可能抛出或向上传递异常时补充对应 `@throws`。
- 新增 PHP 方法同时补充项目 PHP 版本支持的参数类型和返回类型声明；类型声明不能代替 PHPDoc。
- 修改方法签名或行为时同步更新注释。
- PHP 方法新增、移动或替换后，检查相邻方法之间的空行及周边格式。
- Gamesh 请求对象的新增属性必须保留框架解析所需的 `@var` 注释；数组注明元素类型（如 `int[]`），同时按现有规范添加 `ApiModelProperty`。
- 完成代码后检查新增方法及请求属性的注释是否齐全。

## 工具调用

- 可选参数没有值时省略该字段，不传空字符串。
- 使用 Read 工具读取普通文件时不传 `pages`；只有读取 PDF 且需要页码范围时才传有效页码。
