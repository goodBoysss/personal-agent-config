# Codex 专属约定

## 图片开场的会话标题

- 图片开场的标题必须帮助用户区分不同会话：写出图片中的具体业务对象、页面、报错或讨论问题，建议 8–20 字，保留工单号等关键标识。标题描述“这次在讨论什么”，不能描述助手“正在看图/提取信息”的动作。
- 禁止使用 `[Image #1]`、`Review attached image`、`识别图中关键信息`、`分析截图内容`、`提取图片文字`、`查看图片`、`帮我看看` 等通用标题。自检：如果换一张毫不相关的图片，这个标题仍然适用，就不要使用它。例如截图明确显示头条账户删除条件时可命名“头条账户批量删除条件”；明确讨论 ROI 差异时可命名“头条实时与分时 ROI 差异”。例子只用于说明标准，不得套用到无关图片。
- 先理解图片和用户说明，再命名。只有图片时，可以使用图片中可确认的具体主题，不得猜测用户要修复、开发或排查什么；连具体主题也无法确认时暂不调用命名脚本，等待后续信息。后续轮次发现已有名称是上述套话时，应根据已明确的主题纠正，不能将套话当作“已有具体名称”永久保留。保留用户明确指定的名称。
- 在图片开场的首次明确任务时，自动执行 `python3 {{BASH_ROOT}}/bin/codex-session-title.py '具体中文标题'`，无需用户提醒；若后续才明确图片主题，则在该轮自动执行。正确引用参数，避免 shell 插值。命名后继续完成原任务。
- 脚本只按当前 `CODEX_THREAD_ID` / `CODEX_SESSION_ID` 定位会话，保留已保存的具体名称；直接设置 Otty 的持久标签属性，同步侧栏及窗口标题。不向输入框发送 `/rename`、按键或文本，不读取、清空或提交用户草稿；输入框非空也可安全同步。不要用临时 OSC 标题或 Otty CLI 返回成功代替实际回读。
- 脚本在 `~/.codex/session-title-sync/` 记录自动标题归属，以便标签复用时更新旧的自动名称；其他具体标签名称按用户手动名称保护。UUID（含状态前缀或旧会话 UUID）、图片占位、通用看图套话都不算具体名称。
- 这是本机标题偏好，无须单独询问用户；不为命名额外启动模型、发送消息或创建后台轮询服务。界面未就绪时脚本只做有限重试；失败返回非零状态。读取具体失败原因后修复或重试，不能笼统要求用户恢复会话，也不能声称标签已修好。遇到其他具体名称冲突时不得盲目覆盖。
- 命名成功不能只看“已保存”。本轮结束前运行同一脚本并加 `--check`，核对保存名称、侧栏标签、终端标题一致。检查失败时按具体原因同步并重新检查；仍失败则在最终回复明确说明尚未同步及原因。已有具体会话名称必须保留，但界面仍显示 UUID 或图片占位时，应同步已有名称，不能把“保留名称”当成跳过界面修复的理由。
